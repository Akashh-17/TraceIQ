KEY CONCEPTS TO REMEMBER
-------------------------

1. REPOSITORY PATTERN (the missing piece from Phase 2)
   Phase 2: Controller → Service → (nothing, just randomUUID())
   Phase 3: Controller → Service → Repository → Prisma → PostgreSQL

   Repository = the only file that talks to the database.
   Think of it as the "storage clerk". The service says "store this event",
   the repository figures out HOW (SQL, ORM, etc).

   Why not just call Prisma directly from the service?
   - If you swap Prisma for raw SQL tomorrow, you change ONE file (the repository).
   - The service doesn't care. The controller doesn't care.
   - It also makes unit testing easy — mock the repository, skip the real DB.

2. SINGLETON PRISMA CLIENT
   src/config/prisma.ts exports ONE shared PrismaClient instance.
   Every repository imports that same object.
   Why? Because each PrismaClient opens a database connection pool.
   Creating many clients = wasting connections = slower app.
   One client shared everywhere = correct.

3. PRISMA v7 QUIRK
   In Prisma v7, the database URL is NOT in schema.prisma.
   It lives in prisma.config.ts at the project root.
   The schema.prisma datasource block has NO url field — Prisma reads it from the config.

4. MIGRATIONS
   When you change schema.prisma:
     npx prisma migrate dev --name describe_your_change
   This does THREE things:
   a) Generates a SQL file in prisma/migrations/
   b) Runs that SQL against your DB
   c) Re-generates the Prisma client (TypeScript types update automatically)

   Never edit the DB manually. Always go through migrations.
   This way the migration folder is a complete history of every DB change ever made.

5. MULTI-TENANCY (tenantId everywhere)
   Every audit_event row has a tenantId.
   Every query filters by tenantId FIRST.
   This ensures Company A can never see Company B's events,
   even if they somehow got Company B's event ID.
   This is enforced at the repository level — it's never optional.

6. IMMUTABILITY RULE
   AuditEvents have NO updatedAt field. On purpose.
   An audit log is a permanent record. You never edit history.
   Once written → never changed. Prisma won't even offer an `.update()` path
   if you design it this way.

7. devTenantId (temporary placeholder)
   Phase 3 has no auth yet. So where does tenantId come from?
   We seed a test tenant in the DB and put its ID in .env as DEV_TENANT_ID.
   The controller reads env.devTenantId and passes it to the service.
   The SERVICE doesn't read env — the controller does, then passes it in.
   Phase 4 replaces this one line: env.devTenantId → req.tenantId
